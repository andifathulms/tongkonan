## Design Specificity Verdict

Authored to an unusual degree — the layout is the content's metaphor, the palette is an argument, the copy is voiced. The character risk is density, not blandness. Deterministic scan: zero findings again (exit 0); browser overlays skipped (no automation). The score held at 31 while the issue set changed completely: the previous P1s (findability, touch map, aria leak) are resolved, and clearing them exposed the next stratum.

## Priority Issues

1. [P1] Every working route ships all 35 tradition generators (~2.1MB raw / 472KB gz) plus three.js with no loading state — the phone reader pays seconds of blank canvas for 34 houses they didn't ask for. Fix: lazy per-tradition build behind dynamic import (neutrality survives); paint the server-side silhouette in the viewport until the scene mounts. → optimize
2. [P1] Derivation and drawing export exist for 1 of 35 houses and vanish silently elsewhere (Derivation.tsx / DrawingExport.tsx return null) — a teacher discovers the absence only by not finding it. Fix: a stated one-line gap in the rail linking to the tongkonan's worked example. → clarify
3. [P1] The provenance class names are never defined in the UI — measuredGloss/canonGloss/interpolatedGloss exist in both locales in lib/i18n.ts and render nowhere; "Kanon" is load-bearing jargon for the student audience. Fix: surface the glosses in ProvenanceStrip and SplitLegend. → clarify
4. [P2] The Moved pages are stale: <title> still "Pasak", copy never says the page moved, 35 undifferentiated links; splash comment says "Both houses", registry header says "twelve buildings". Fix: correct title, one-sentence explanation, single primary link, collapse the rest. → polish
5. [P2] /banding is under-connected (one link, bottom of landing) and cramped at 320px (forced grid-cols-2). Fix: a "Bandingkan" door on each house front door pre-filled with ?a=<house>; stack columns below ~360px. → layout
